# CampusFix AI — AI Development Checklist

## 🔴 P0 — MUST HAVE

### 1. Image → Issue Classification

 [ ] Accept image upload
 [ ] Classify incident category
 [ ] Support at least 5–7 categories

   [ ] Electrical
   [ ] Plumbing
   [ ] Waste
   [ ] Infrastructure
   [ ] Furniture
   [ ] RoadPavement
   [ ] Other
 [ ] Return confidence score
 [ ] Add low-confidence fallback to `OtherUnknown`
 [ ] Do not force a classification when confidence is too low

Example output

```json
{
  category Electrical,
  confidence 0.93
}
```

---

### 2. AI Severity  Risk Assessment

 [ ] Generate severity `LOW  MEDIUM  HIGH  CRITICAL`
 [ ] Explain why the severity was assigned
 [ ] Identify possible risk
 [ ] Recommend immediate action
 [ ] Recommend responsible department

Example

```json
{
  severity HIGH,
  risk Possible electrical shock,
  recommended_action Restrict access to the area,
  department Electrical Maintenance
}
```

---

### 3. Structured AI Output

 [ ] Force LLM response into JSON
 [ ] Validate JSON with Pydantic
 [ ] Reject malformed output
 [ ] Add fallback values
 [ ] Keep the schema consistent for the backend

Target schema

```json
{
  category Electrical,
  confidence 0.93,
  severity HIGH,
  risk Possible electrical shock,
  action Restrict access,
  department Electrical Maintenance
}
```

---

### 4. Duplicate Incident Detection

 [ ] Convert incident descriptions into embeddings
 [ ] Store embeddings
 [ ] Generate embedding for new incident
 [ ] Compare against existing incidents
 [ ] Use cosine similarity
 [ ] Set a similarity threshold
 [ ] Return matching incident ID
 [ ] Show similarity percentage

Example

```text
⚠ Possible Duplicate

Existing Incident INC-018
Similarity 91%
Location Block B
Issue Water leakage
```

---

### 5. Confidence + Uncertainty

 [ ] Store classification confidence
 [ ] Show confidence to admin
 [ ] Define a confidence threshold
 [ ] Route low-confidence cases to human review
 [ ] Never invent missing information
 [ ] Clearly distinguish AI prediction from certainty

Example

```text
AI Confidence 48%

⚠ Manual verification required
```

---

# 🟠 P1 — MAKES THE AI STRONG

### 6. Multimodal Reasoning

 [ ] Use image + description + location
 [ ] Give all relevant context to the LLM
 [ ] Let context influence severity
 [ ] Test same image under different contexts

Example

```text
Image Water leak

Location A Electrical Lab
Description Water leaking beside power outlet
→ HIGH severity

Location B Garden
Description Small amount of water near plants
→ Lower severity
```

---

### 7. AI-Generated Incident Summary

 [ ] Convert messy user text into a concise report
 [ ] Remove unnecessary wording
 [ ] Preserve important facts
 [ ] Do not invent details

Example

```text
Input
There's some water dripping from the ceiling in block B near
the computer room and it's getting worse.

AI Summary
Water leakage detected near the computer room in Block B.
The issue appears to be worsening and may pose a slip hazard
and equipment-damage risk.
```

---

### 8. Automatic Department Assignment

 [ ] Map incident to responsible department
 [ ] Electrical → Electrical Maintenance
 [ ] Water leak → Plumbing
 [ ] Broken furniture → Facilities
 [ ] Garbage → Sanitation
 [ ] Road damage → Civil Works

 [ ] Generate a responsible team

### 10. Human-in-the-Loop

 [ ] Automatically accept high-confidence predictions
 [ ] Flag uncertain predictions
 [ ] Allow admin to override AI result
 [ ] Store final human decision
 [ ] Use corrections for future model improvement

```text

       ↓

       ↓
Human review
```

# 🧠 MODEL  AI ENGINEERING CHECKLIST

## Vision Model

 [ ] Use pretrained model
 [ ] Avoid training from scratch
 [ ] Keep inference fast
 [ ] Record model version
 [ ] Record confidence
 [ ] Test on unseen images
 [ ] Handle blurry images
 [ ] Handle irrelevant images

## LLM

 [ ] Use structured JSON output
 [ ] Keep prompts deterministic
 [ ] Provide only relevant context
 [ ] Validate output
 [ ] Handle malformed responses
 [ ] Handle API timeout
 [ ] Handle API failure
 [ ] Implement fallback behavior

## Embeddings

 [ ] Generate incident embeddings
 [ ] Store embeddings
 [ ] Compare new incidents with existing incidents
 [ ] Use cosine similarity
 [ ] Tune duplicate threshold
 [ ] Test true duplicates and non-duplicates

## API

 [ ] `POST aianalyze`
 [ ] `POST aiduplicate-check`
 [ ] Validate request body
 [ ] Validate response schema
 [ ] Return predictable JSON
 [ ] Add error handling
 [ ] Log inference time

# 🎯 FINAL AI GOAL

The AI should be able to say

 I don't just recognize the problem. I understand the context, assess the risk, recommend the appropriate response, detect duplicate reports, explain my decision, and request human review when I'm uncertain.

That should be the core AI story of the project.
